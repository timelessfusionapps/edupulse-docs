# Dashboard Live Runtime Integration

This document defines the final future implementation strategy for connecting the Dashboard components: UI ↔ Bloc ↔ Repository ↔ Datasource ↔ Firebase. It serves as the executable blueprint for the engineering phase.

## 1. UI ↔ Bloc Integration
- **Selector Boundaries:** Every independent UI widget (e.g., `KPICardGrid`, `RevenueChart`, `ActivityFeedList`) will consume state exclusively via localized selectors (`ref.watch(...select(...))`).
- **Rebuild Segmentation:** The main `DashboardScreen` acts only as a scaffold. It provides layout structural integrity but does not listen to data state.
- **Event Routing:** User interactions in the UI (e.g., pull-to-refresh, changing a date filter) fire intents (methods or events) on the Bloc instance without executing any direct business logic.

## 2. Bloc ↔ Repository Integration
- **Runtime Orchestration:** The Bloc requests streams and futures from the Repository. It handles mapping Domain models into UI-friendly ViewModels.
- **Stream Coordination:** The Repository exposes `Stream<DomainModel>` which the Bloc subscribes to. The Bloc translates stream events into UI State emissions.
- **Repository Boundaries:** The Repository is completely agnostic to UI framework logic (no Flutter dependencies). It serves as a pure Dart interface enforcing business rules.

## 3. Repository ↔ Datasource Integration
- **Analytics Queries:** The Datasource defines precise Firestore queries to fetch pre-aggregated analytics documents.
- **Realtime Streams:** The Datasource utilizes `snapshots()` to stream data. It applies necessary decoding from JSON to DTOs.
- **Caching Strategy:** All Datasource reads default to `GetOptions(source: Source.serverAndCache)` or leverage standard `snapshots(includeMetadataChanges: true)` to ensure immediate local cache yields before network fulfillment.

## 4. Dashboard Live Stream Integration
- **KPI Streams:** A single listener attached to an aggregation document (e.g., `metrics/dashboard_kpis`). Avoids counting thousands of individual documents client-side.
- **Leaderboard Streams:** A limited query stream (`limit(5)` ordered by `points DESC`).
- **Feed Streams:** A hybrid stream. The realtime subscription listens only for new events (`where('timestamp', '>', lastLoadTime)`).
- **Chart Streams:** Listens to periodic snapshot documents generated by backend Cloud Functions.

## 5. Offline Runtime Integration
- **Cached Rendering:** UI receives immediate data via the Datasource's local cache resolution.
- **Reconnect Safety:** The `includeMetadataChanges: true` on streams ensures the Bloc is notified when data transitions from "cached" to "synced" status, allowing the UI to drop the "Offline" indicators automatically.
- **Retry Workflows:** Mutations (like Quick Actions) are executed against the Firestore SDK which natively queues writes if offline. The Datasource returns success optimistically to the Repository.

## 6. Dashboard Realtime Rendering Rules
- **Smooth Updates:** All integer transitions in KPIs must utilize `ImplicitlyAnimatedWidget` derivatives (e.g., `TweenAnimationBuilder`).
- **Animation-Safe Rendering:** Chart libraries (e.g., fl_chart) must be configured to animate path changes smoothly.
- **Rebuild-Safe Rendering:** Items in lists must utilize strict `Key` assignments to allow Flutter's diffing algorithm to effectively recycle widgets without full rebuilds.

## 7. Dashboard Runtime Safety Rules
- **Memory Safety:** Streams are meticulously bound to the Bloc lifecycle. Navigation away from the Dashboard completely clears all active listeners.
- **Stream Safety:** Rapid filter changes `cancel()` pending/active streams before establishing new ones.
- **Pagination Safety:** Cursor fetches are locked by an `isFetching` boolean to prevent duplicate concurrent network requests.
- **Rebuild Safety:** Deep equality checks (or `Equatable`) ensure that if identical data streams in, the Bloc does not emit a new state, suppressing unnecessary UI rebuilds.

## 8. Dashboard Validation Requirements
Prior to signing off the implementation, the following validation must be performed and documented:
- **Runtime Validation:** Confirm seamless data flow from Firebase to UI.
- **Stress Testing:** Rapid filter toggling and network interruption tests.
- **Responsive Validation:** Verification on 1440px, 1024px, 768px, and 390px viewports.
- **Realtime Validation:** Verify concurrent device synchronization (e.g., action on Device A appears instantly on Device B).

## Summary
By rigorously isolating state, strictly enforcing unidirectional data flow, and respecting stream lifecycles, the Dashboard will operate as a highly resilient, memory-efficient, and offline-capable control center perfectly aligned with the validated EduPulse platform standards.
