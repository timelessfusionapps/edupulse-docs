## Purpose
Defines how Role-Based Access Control physically alters the user interface.

## Principle: Hide vs Disable
- **Irrelevant Actions**: Actions a user will *never* have permission to do should be hidden completely (e.g., a Teacher should not see an "Archive Student" icon if only Principals can archive).
- **Conditionally Relevant Actions**: Actions a user *might* have permission to do under different circumstances should be visible but disabled (greyed out) with a tooltip explaining why (e.g., "Only School Admins can edit historical points").

## Visual Cues
- **Read-Only Mode**: When a user (like a Student or Parent persona) views the list, all mutation actions (Edit, Delete, Add Points) are stripped from the UI. The list becomes a pure visualization tool, maintaining structural integrity without leaving empty layout gaps.
