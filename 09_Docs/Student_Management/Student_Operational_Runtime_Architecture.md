# Student Operational Runtime Architecture

## Overview
This document specifies the overarching runtime rules binding the UI, Bloc, and Datasource layers for the Student Management module.

## Core Architectural Rules
1. **Source of Truth**: The `StudentState` generated by `StudentBloc` is the absolute and ONLY source of truth for the UI layer. 
2. **Context Preservation**: Changing filters, executing searches, or turning pagination pages MUST NOT destroy the underlying connection or reset the user's workflow unexpectedly. Context must be preserved across actions.
3. **Optimistic Mutations**: UI triggers a mutation event -> Bloc marks mutation pending -> Repository attempts write -> Bloc resolves mutation pending flag upon success/failure. 
4. **Resiliency**: Reconnection logic, retry policies, and timeout handlers are abstracted into the Datasource and Repository. The UI simply renders the status (`isOffline`, `error`) without needing to implement retry algorithms itself.

## Implementation Guidelines
- The Bloc must implement concurrent event processing for reads and mutations to prevent UI blocking.
- Avoid tight coupling between UI widgets and Firebase concepts; widgets must not know about `QuerySnapshot` or `DocumentReference`.
