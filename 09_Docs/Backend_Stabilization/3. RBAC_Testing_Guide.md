# RBAC Testing Guide

## Purpose
Provides documentation on testing roles and cross-tenant boundaries.

## Architecture & Design
Pre-seeded 6 standard personas (e.g. superadmin, principal, teacher) mapped to specific tenants, with custom claims injected strictly at seed-time.

## Operational Impact
This architecture enables frontend developers to immediately begin work on business logic without worrying about manual backend configuration, Auth token tampering, or missing test data. The use of `--export-on-exit` means you don't lose data when shutting down the emulator, but you can always reset via `npm run seed:reset`.

## Security & Risk Mitigation
- **Production Kill-Switches**: Seeding scripts check strictly for `FIRESTORE_EMULATOR_HOST`. If missing, the script halts instantly to protect production.
- **Tenant-Safe**: Cross-tenant bleeding is strictly tested using `teacher_2` assigned to `school_2`.

## Health Verification
Developers can run `npm run validate:backend` to confirm the environment is healthy, verifying that custom claims actually map to standard Firestore documents.
