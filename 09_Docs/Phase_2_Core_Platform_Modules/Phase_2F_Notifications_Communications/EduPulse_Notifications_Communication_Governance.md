# 1. Purpose

This document defines the governance rules for all communication activities within EduPulse.

It governs:

- Notifications
- Announcements
- Broadcasts
- Templates
- Communication Preferences
- Delivery Tracking
- Read Tracking
- Audit Trails
- Communication History

The purpose is to ensure:

- Consistency
- Auditability
- Security
- Multi-Tenant Isolation
- Academic Year Compliance

---

# 2. Governance Principles

All communication records must follow:

### Audit First

Every action must be auditable.

---

### School Ownership

Communication belongs to the school.

Users create communications.

Schools own communications.

---

### Archive Over Delete

Communication records are archived.

Permanent deletion is prohibited.

---

### Academic Year Boundaries

Communication history remains tied to the academic year in which it occurred.

---

# 3. Communication Ownership Governance

Owner:

```text
School
```

Audit Records Maintain:

- Created By
- Sent By
- Modified By
- Archived By

Ownership never transfers to individual users.

---

# 4. Notification Governance

Notifications are categorized as:

### System Notifications

Generated automatically.

Examples:

- Student Created
- Achievement Earned
- Event Reminder

---

### Manual Notifications

Generated by users.

Examples:

- Parent Message
- Class Update
- House Notice

---

# 5. Notification Lifecycle Governance

Lifecycle:

```text
Draft
↓
Scheduled
↓
Sent
↓
Archived
```

Soft Delete permitted.

Hard Delete prohibited.

---

# 6. Announcement Governance

Announcements act as notice-board content.

Required fields:

- Title
- Body
- Publish Date

Optional fields:

- Image
- Expiry Date
- Pin Status

---

# 7. Announcement Editing Governance

Published announcements:

```text
CANNOT BE EDITED
```

Required process:

```text
Archive Existing
↓
Create New Version
```

---

# 8. Announcement Archival Governance

Announcements may be archived.

Archived announcements:

- Hidden from active view
- Preserved historically
- Available in audit history

---

# 9. Broadcast Governance

Broadcasts are manually initiated communications.

Examples:

- Parent Circular
- School Notice
- House Communication

Broadcast audience limits are configurable per school.

---

# 10. Scheduled Broadcast Governance

Broadcasts support:

### Send Now

### Schedule Later

Scheduling must be recorded in audit logs.

---

# 11. Communication Channel Governance

V1 Channels:

- In-App
- WhatsApp

Future Channels:

- Email
- SMS
- Push Notifications

---

# 12. Channel Activation Governance

Platform Admin controls:

- Email Access
- SMS Access

School controls:

- In-App Activation
- WhatsApp Activation

---

# 13. WhatsApp Governance

WhatsApp Templates are governed separately.

Reasons:

- Channel Constraints
- Message Length Requirements
- Provider Compliance

WhatsApp templates cannot reuse In-App templates directly.

---

# 14. Template Governance

Templates support:

```text
Draft
↓
Active
↓
Archived
```

Schools may:

- Create
- Edit
- Archive

Templates may not be permanently deleted.

---

# 15. Template Version Governance

When active templates are edited:

A new version must be created.

Historical versions remain preserved.

---

# 16. Multi-Language Governance

Supported Languages:

- English
- Arabic
- Gujarati
- Hindi

Language records remain independent.

Translation content must not overwrite existing language variants.

---

System Categories:

- Events

- Discipline

# 18. Recipient Governance

Supported recipients:

- Students
- Parents

- Classes

# 19. Parent Communication Governance

Primary Contact receives notifications.

Future support for multiple contacts remains possible.

V1 governance:

```text
Primary Contact Only
```

---

# 20. Student Lifecycle Governance

When a student:

- Leaves
- Graduates
- Is Archived

Future notifications stop immediately.

Historical communication remains preserved.

---

# 21. Event Governance

Event Owners may:

- Send Event Notifications
- Send Event Announcements
- Schedule Event Reminders

Without School Admin intervention.

---

# 22. Event Reminder Governance

Reminder rules are configurable.

Examples:

- 7 Days Before
- 3 Days Before
- 1 Day Before
- 1 Hour Before

---

# 23. Points Governance

Schools determine whether notifications are generated for:

- Points Awarded
- Points Deducted
- Achievement Earned
- Badge Earned
- Recognition Awarded

Configuration remains school-specific.

---

# 24. Deduction Governance

Parent notifications for deductions must include:

- Deducted Points
- Reason
- Deductor

Approver details remain internal.

---

# 25. House Communication Governance

House communications may target:

- House Students
- House Parents

House Coordinators may initiate communication.

---

# 26. Class Communication Governance

Class Teachers may communicate only with:

- Assigned Classes
- Assigned Class Parents

Cross-class communication prohibited.

---

# 27. Read Tracking Governance

Opening a communication automatically generates:

```text
readAt
```

No acknowledgement button required.

---

# 28. Delivery Tracking Governance

Supported states:

```text
Queued
Sent
Delivered
Read
Failed
```

State transitions must remain auditable.

---

# 29. Retry Governance

Failed WhatsApp communications follow configurable retry policies.

Retry actions generate audit records.

---

# 30. Preference Governance

Preference management supported for:

- Parents
- Teachers

Future Portal Ready.

# 31. Analytics Governance

Schools may view:

- Sent Counts
- Delivered Counts
- Read Counts
- Failed Counts

# 32. Recipient-Level Analytics Governance

Schools may view:

```text
Recipient
↓
Read Status
```

for communication accountability.

---

# 33. Attachment Governance

V1:

```text
Images Only
```

Future:

```text
Images
Documents
```

Attachment validation required.

---

# 34. Academic Year Governance

At Academic Year Closure:

Schools choose:

- Cancel Scheduled Communications
- Move Communications
- Archive Communications

Recurring communications terminate automatically.

---

# 35. Communication History Governance

Active visibility:

Current Academic Year

After year closure:

```text
Archive
```

Historical records remain searchable.

---

# 36. Soft Delete Governance

Permitted.

Soft Delete must capture:

- Deleted By
- Deleted At
- Reason

---

# 37. Hard Delete Governance

Prohibited.

No communication records may be permanently removed.

---

# 38. Offline Governance

Offline-generated communications may queue locally.

Upon synchronization:

- Original timestamps preserved
- Delivery history preserved

---

# 39. Audit Governance

Required fields:

- Actor
- Timestamp
- Action
- Channel
- Recipients
- Template
- Status

# 40. Dynamic Group Governance

Dynamic Groups remain rule-driven.

Membership recalculates automatically.

Manual editing prohibited for dynamic groups.

# 42. Future Mobile Governance

# 44. Multi-Tenant Governance

All communication records remain scoped to:

```text
schools/{schoolId}
```

Cross-tenant visibility prohibited.
