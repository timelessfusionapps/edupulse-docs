# EduPulse Design System V1

## Overview

EduPulse follows a modern operational SaaS design language focused on:
- clarity
- operational efficiency
- responsive scalability
- premium enterprise aesthetics
- educational gamification with restraint

The system is intentionally designed to support:
- high-density operational workflows
- multi-role interfaces
- responsive admin systems
- scalable data-heavy modules

The design language should feel:
- premium
- modern
- fast
- calm
- highly usable
- enterprise-grade

WITHOUT:
- visual clutter
- oversized cards
- childish educational styling
- excessive gradients
- marketing-page aesthetics

---

# 1. Core Design Philosophy

EduPulse is:
NOT a marketing website.

EduPulse is:
a real operational educational SaaS platform.

The UI must prioritize:
1. fast scanning
2. operational clarity
3. responsive stability
4. data readability
5. workflow efficiency

---

# 2. Layout Architecture

## Standard Workspace Structure

EduPulse uses:
Dark Navigation + Light Workspace.

### Navigation
- dark sidebar
- persistent navigation
- premium SaaS hierarchy

### Workspace
- light operational content area
- high readability
- minimal distractions

- Indigo/slate palette

# 6. Card Standards

## KPI Cards
KPI cards must remain:
- compact
- lightweight
- informational

Avoid:
- oversized dashboard cards
- excessive gradients
- decorative visuals

## Card Radius
Moderate only.

Avoid extreme rounding.

---

# 7. Table Design Standards

Operational tables are a CORE EduPulse UI pattern.

## Table Rules
- compact row heights
- strong scanning ability
- sticky headers
- subtle hover states
- zebra rhythm optional
- operational density

## Table Hover
Use:
subtle indigo hover overlays.

## Table Shadows
Very soft only.

Avoid floating table effects.

---

# 8. Responsive Standards

## Desktop
Primary operational workspace.

## Tablet
Condensed operational workspace.

Hide:
low-priority columns.

Maintain:
workflow efficiency.

## Mobile
DO NOT shrink desktop tables.

Mobile must use:
purpose-built mobile layouts.

Example:
Desktop Table → Mobile Cards.

---

# 9. Mobile Design Standards

## Mobile Cards
Cards must remain:
- compact
- touch-friendly
- operationally dense

Avoid:
- giant cards
- excessive spacing
- dashboard-like layouts

## Mobile Filters
- horizontal chips
- bottom sheets
- collapsible filters

---

# 10. Search & Filters Standards

## Search
- visually anchored
- compact
- operational

## Filters
Grouped segmented controls.

NOT disconnected floating buttons.

---

# 11. Pagination Standards

Pagination must remain:
- compact
- subtle
- highly usable

Avoid:
- giant pagination controls
- oversized buttons

---

# 12. Color Philosophy

## Primary Palette
Indigo / Slate.

## Accent Colors
Used sparingly:
- green = success
- red = alerts
- orange = warnings
- blue = information

## Gamification
Subtle only.

Never childish.

---

# 13. Shadow Philosophy

Use:
soft low-elevation shadows.

Avoid:
- neumorphism
- heavy floating cards
- exaggerated blur

---

# 14. Animation Standards

Animations should feel:
- subtle
- premium
- responsive

Standard:
140ms–180ms.

Avoid:
- bouncy animations
- excessive motion
- distracting transitions

---

# 15. Responsive Safety Standards

ALL modules MUST validate:
- zero RenderFlex overflow
- stable scrolling
- stable tables
- stable pagination
- stable filters
- stable search layouts

Mandatory validation widths:
- 1440px
- 1280px
- 1024px
- 900px
- 768px
- 600px
- 430px
- 390px

---

# 16. Operational Density Philosophy

EduPulse favors:
controlled operational density.

Avoid:
- oversized whitespace
- giant cards
- low-information layouts

The system should feel:
efficient,
not cramped.

---

- empty states
- offline states
- retry states
