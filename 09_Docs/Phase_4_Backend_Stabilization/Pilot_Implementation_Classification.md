# EduPulse Permanent Documentation Standard
## Pilot Implementation Classification

---

# Effective From

Phase 4 onwards.

This becomes a permanent documentation standard for the EduPulse project.

All future documents generated by Antigravity must follow this standard.

---

# Mandatory Section

Every execution document must contain the following section.

# Pilot Implementation Classification

Each feature, module, work package, task, or implementation item must be assigned one of the following classifications.

---

## 🟢 Pilot Priority

Definition

Mandatory before the TEMS pilot goes live.

These items block deployment.

Examples

- Authentication
- School creation
- User management
- Teacher login
- Student management
- Award points
- Activities
- Houses
- Critical security rules
- Required repositories
- Critical Firestore collections

---

## 🔵 Deferred After Pilot

Definition

Not required for the initial TEMS deployment.

Must still be implemented later.

Deferred DOES NOT mean optional.

Every deferred item remains part of the official EduPulse roadmap.

Examples

- Executive aggregation
- AI services
- Predictive analytics
- Cross-school reporting
- Platform broadcasts
- Advanced recovery automation
- Enterprise reporting
- Multi-region optimization

---

# Deferred Register

Every execution document must end with:

# Deferred Implementation Register

Purpose

Maintain a permanent inventory of everything intentionally postponed.

Nothing may be removed.

Nothing may disappear.

Nothing may be forgotten.

Each entry must include:

Feature

Current Document

Original Planned Stage

Reason for Deferral

Risk of Deferral

Recommended Future Stage

Status

Planned

In Progress

Completed

---

# Cross-Reference Requirement

Whenever a document creates new deferred work, it must reference:

- Previous Deferred Register entries that relate to it.
- Existing Phase 4 Roadmap stages.

This ensures deferred work remains connected across documents instead of becoming isolated.

---

# Permanent Architectural Rule

The EduPulse implementation strategy is based on phased delivery.

Deferral is an implementation sequencing mechanism.

It is NOT a scope reduction mechanism.

Any feature marked as Deferred After Pilot remains part of the official EduPulse architecture and must continue to appear in all future planning until implemented and certified.

---

# Documentation Review Requirement

Before closing any implementation document, Antigravity must verify:

✓ Every task has a Pilot Priority.

✓ Every deferred task appears in the Deferred Implementation Register.

✓ No deferred work has been removed from the roadmap.

✓ All deferred items reference the stage in which they will be implemented.

If any of these checks fail, the document must not be certified as complete.
